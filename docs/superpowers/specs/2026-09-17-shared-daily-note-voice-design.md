# 双端每日英文短句的生活感：设计

日期：2026-09-17。Carlos 已认可内容方向与匿名天气/时段素材；Grok 已完成只读文案审校。本文件只规定文案改动，不授权微信真发或定时设置变更。

## 目标与取舍

默认每天仍由 DeepSeek 原创一条 1–20 个可打印 ASCII 字符的英文短句，同一次双端推送共用同一句。它可以是一句跨时区的交班、无回复压力的惦念、一点基于真实天气的小细节、温柔的距离玩笑，或偶尔可不回答的小问题；不是五行新模板、预设句库或按星期轮播。基调保持亲密、克制、自然，不用空泛誓言、情绪勒索或催回复。

只改提示词最省事，却无法让默认推送引用任何当天真实素材；增加模板字段能写长内容，但现有测试号卡片可能隐藏新字段，还需人工改模板。选定中间路径：在现有短句位置内，传入两端匿名时段和已归类的天气线索，保持手动 `theme`、`exact` 与模板原样。此改动不实施旧规格中的历史 artifact 或跨日严格去重；天气/提示词变化不能保证绝不重复。

## 数据与行为

`src/main.py` 组装天气后提前取得两地时钟，复用到最终模板，只将时钟转换成 `morning`（05–11）、`afternoon`（12–17）、`evening`（18–22）、`night`（23–04）。天气去掉严格匹配的末尾摄氏温度后，只接受固定描述的归类：`Clear/Fair/Sunny` → `clear`，`Ptly cloudy/Cloudy/Overcast` → `cloudy`，`Rain/Drizzle/Showers/Icy rain/Icy driz` → `rainy`，`Snow/Snow shwr` → `snowy`，`Fog` → `foggy`，`Storm/Hail storm` → `stormy`。未知、离线或不合格值不提供天气线索。绝不把天气供应商原始文本、城市名、时区 ID、精确时间、气温、OpenID、关系日期或聊天内容传给 DeepSeek。本轮不额外传日期；不得让模型编造当天事件或特殊节日。

`src/deepseek_line.py` 只接收已经归一化的类别，再做一次允许值校验。无手动主题时，提示词要求模型自主选一个合适角度写当天原创英文短句，且同一句必须在两端都读得通，不能只对其中一人说早安。以陈述和轻触为主，问句只作为偶尔可无视的变化，不制造回复义务。天气与时段是可用事实，不要求每次硬塞进去；不得凭空生成咖啡、散步、照片、共同回忆、对方心情或正在做的事。可用素材只有这些时，所谓“小细节”只能是天气/时段细节。宁可简短平实，不为幽默强行缩写成不自然的电报腔。有手动 `theme` 时，它代替五种默认方向且不叠加天气/时段素材，仍须遵守真实性和格式边界；有效 `exact` 保持原样且跳过 API。现有长度、字符、输出格式、失败即不发、两端同句及不重试微信的规则不变。

模型输出可能仍然平庸、失真或撞句；不用跨日状态或固定日历，就不能保证问句有严格的每周上限或两天绝不相同。短字符串检查不能证明情感质量。预览只能检验一次生成与模板字段，不等于未来每日稳定、微信接口接受或手机收到。本阶段不复制 X 原帖文字进仓库或提示词。

## 验证与发布边界

- 先写失败测试，再改实现。覆盖双端只生成一次且内容相同、手写 `exact` 不调用 API、`theme` 继续进入提示词而不进日志、无天气时不传伪事实、恶意/未知天气文本不进提示词、时段是可用但非强制的素材。检查提示词明确约束双端可读、无催回、无编造，但不把“模型必然遵守”伪装成可机械保证的测试结果。
- 既有 `<=20` 可打印 ASCII、无效文案至多三次生成、API/鉴权失败停在微信发送前的测试须继续通过；README 说明新语气与真实性边界。
- 本地全套测试与模拟预览先通过，再决定是否发布到远端。只有另行确认才触发真发；GitHub 运行成功、接口受理与手机实收必须分别说明。
