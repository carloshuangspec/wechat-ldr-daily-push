# DeepSeek-only daily line for WeChat

Date: 2026-09-16. This spec supersedes the provider choice in `2026-09-16-editable-daily-gemini-line-design.md`: Carlos selected option B, **DeepSeek only**, after reviewing Gemini-primary/DeepSeek-backup, DeepSeek-only, and manual-only options. All one-day editing, recipient gates, English template, dates and fail-closed requirements from that spec still apply.

## Behavior

The final short English line normally comes from one new DeepSeek API request for each run; it never rotates static lines and does not call Gemini. If that response contains invalid text, the generator may make up to two more requests **before** any WeChat send; auth, HTTP, network and malformed-response failures are not retried. Three invalid texts still fail closed, and no WeChat send is ever retried. The dated `DAILY_MESSAGE_CONFIG` Secret is a strict JSON object with a Shanghai date and a nonempty `theme` and/or `exact`. On the matching CN day, a valid `exact` line wins unchanged without any AI request. Otherwise a theme informs the DeepSeek prompt, or the generic prompt is used. The US/SELF jobs do not receive the CN override. The API does not receive names, private chat archives or relationship history; the high-level approved theme is sent only for the matching CN day. Since DeepSeek may cache input/output prefixes, neither the helper nor documentation should imply zero retention.

Use the official HTTPS `POST https://api.deepseek.com/chat/completions` endpoint, `Authorization: Bearer <DEEPSEEK_API_KEY>` header, `model: deepseek-flash`, `stream: false`, and `thinking: {"type":"disabled"}` for this short request. Disable redirects, retain normal TLS validation, impose a bounded timeout. The only accepted response is HTTP 200 with one completion, `finish_reason: stop`, one nonempty string `message.content`, with only surrounding ordinary ASCII spaces removed. Reject any newline, control, non-ASCII, quote wrapper, extra prose, or line over 20 printable characters. The full two-line `Known: ≈N days\n<line>` field must fit 64 characters and survive template rendering untruncated. Log only `line_source=deepseek|manual`, dated override status and sanitized diagnostics; do not log the prompt, theme, API Key, request, raw response, reasoning, or exception. The dry-run preview still prints the complete rendered WeChat message and is visible to authorized repo log readers.

If no valid exact override exists and the Key is missing or DeepSeek fails/returns an invalid completion, abort before any WeChat send. Never send weather-only or a fixed/static line. Weather's existing nonfatal fallback is unaffected. Manual CN live remains gated by `slot=cn`, `mode=live-cn`, exact `SEND_CN_ONCE` on owner-triggered first run of remote main. `ENABLE_CN_DAILY` remains absent/off until separate user confirmation after actual phone receipt; US scheduled remains preview only. One live run builds the content once and sends it unchanged. No automatic rerun after an uncertain delivery.

## Configuration and verification

Keep the Key only in Actions Secret `DEEPSEEK_API_KEY` (already streamed from clipboard without displaying it; existence does not establish validity). The existing Gemini Secret/Variable are not read by any new message job. A safe CN preview on deployed `main` validates real API access before one controlled CN live send; unit-test mock log markers and a green job are not proof of live DeepSeek generation. Inspect only the actual `Preview CN` step. If the preview fails, stop and diagnose without sending. If the live API reports success, request confirmation from the recipient's phone before enabling any daily live run. A manual `exact` preview proves the override but not API connectivity, so the provider check needs a generation preview when no exact is active.
