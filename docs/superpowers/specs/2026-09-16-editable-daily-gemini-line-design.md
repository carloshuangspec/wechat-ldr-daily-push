# Editable daily Gemini line for the WeChat push

Date: 2026-09-16

## Goal and boundaries

Keep the existing English test-account template, weather, local times, the confirmed relationship counter, the approximate acquaintance counter, and the next-meeting counter. The final short line is normally freshly generated by Gemini for each run, not selected from a rotating static library. Carlos may override one Shanghai-calendar day's line either with a theme for Gemini or with an exact English line. An exact line wins and is sent unchanged; it does not need or claim Gemini generation that day.

This design changes content generation and its editing workflow only. It does not turn on `ENABLE_CN_DAILY`, add US daily delivery, change recipient routing, or authorize a real WeChat send. The previous Gemini API design's *static fallback* choice is superseded by the user-approved fail-closed rule here; its header-only key handling and response validation still apply.

## Options considered

1. A `workflow_dispatch` text input is easy for a one-off manual run, but a later scheduled run does not inherit that input. It cannot provide tomorrow's unattended override.
2. A dated file committed to the private repository is easy to review, but even a later deletion leaves intimate text in Git history.
3. **Chosen:** one date-bound encrypted GitHub Actions Secret for the current override, plus a small Mac edit helper. It is available to scheduled jobs, is replaced atomically, and does not put the input in Git history or a normal unmasked Actions Variable. The trade-off is one active dated override at a time and a dependency on Carlos's local `gh` login for the helper.

## Daily content and precedence

Use one `DAILY_MESSAGE_CONFIG` Actions Secret containing a single JSON object with a required `date` and optional nonempty `theme` and `exact` strings; at least one of the two text fields is required, and both may be present. Reject unknown fields, duplicate JSON keys, wrong types, noncanonical dates, and invalid text. `date` must be exactly `YYYY-MM-DD` for `Asia/Shanghai`. An absent Secret means normal Gemini generation. A well-formed override for another date is ignored, never carried into a later day. Malformed or invalid configuration stops the run safely instead of guessing a message. Capture the Shanghai date once at assembly and use that same value for CN date counters and override matching, including around midnight. Only the CN preview, manually gated CN live path, and eventually the gated CN scheduled path load this override; self/US jobs do not acquire Rachel's custom content. Use `preview-cn` to examine Rachel's actual override; `preview-us`, `live-self`, or `slot=both` are not evidence of identical SELF/CN text.

For the matching CN date, precedence is:

1. A nonempty `exact` (even when `theme` is also present): use the user's single-line English text verbatim; do not call Gemini for this line. Reject rather than trim, translate, or silently truncate it if it exceeds 20 printable ASCII characters or contains controls/newlines.
2. A nonempty `theme` without `exact`: send only that day's short, user-entered theme to Gemini along with the stable English instructions; accept only a valid generated line. The theme is at most 120 characters, contains no controls/newlines, and may be written in Chinese or English. Its exact text is not printed in logs.
3. No matching override: call Gemini with a generic English prompt about two independent lives and ordinary moments, without feeding it the shared chat, private archives, names, claims about today's events, or assumed thoughts of Rachel.

The result remains the existing two-line `love_line`: `Known: ≈N days` plus the final line. For generated output, validate the *entire* candidate text: reject any CR/LF, quote wrapper, control character, or extra prose instead of slicing off the first line or stripping quotation marks. Removing surrounding ordinary ASCII spaces is the only allowed normalization before validating at most 20 printable ASCII characters. The complete field must fit its existing 64-character budget with no ellipsis truncation. Validate that the rendered template data retains the entire line and never inserts `...`. Other template fields are unchanged. Gemini may independently generate the same wording on different days; this design promises a fresh API request, not mathematical uniqueness.

## Mac editing experience and privacy

A Finder-openable `scripts/edit-daily-message.command` launches a local interactive editor (no server or new login). It prompts for the target Shanghai date (default: the current Shanghai date), an optional theme, and an optional exact line; Carlos may enter either or both. Before saving it shows the date and entered text *locally* for Carlos to confirm. It validates the same length/format constraints, then streams the single JSON value via standard input to `gh secret set DAILY_MESSAGE_CONFIG -R carloshuangspec/wechat-ldr-daily-push --app actions`. It must not place the value in shell arguments, history, a temporary file, a Git commit, or diagnostic output. A successful save reports only the Secret's name and update status; failure reports a sanitized error and cannot pretend the override was installed. A separate deliberate clear action removes only this exact Secret after confirmation. GitHub Secrets cannot be read back into this editor: replacing the override requires entering all desired text again, and no edit history is retained. The helper neither changes `GEMINI_API_KEY` nor enables live sending.

The user can update the Secret again **before the next CN workflow run is queued**; the last successful save before queueing is the active dated override. [GitHub reads repository Secrets at queue time](https://docs.github.com/en/actions/reference/security/secrets#when-github-actions-reads-secrets), so a later edit cannot change a queued/already-started send; check the run's non-sensitive `override_status=active|none|stale` marker and Shanghai date, and never assume a late edit took effect. A theme is sent to Google's Gemini service. An exact line is not sent to Gemini, but the eventual WeChat message and the current dry-run preview expose that line to their respective services/logs. A Secret protects its stored value; it does **not** make the resulting preview text private from people who can read Actions logs. Do not enter archived chats, third-party private details, access credentials, or material Rachel has not agreed to use. The editor does not automatically extract photos, letters, or chats.

## Failure handling and preview truth

Remove the rotating static fallback. If no matching `exact` override exists and the Gemini key is missing, a request fails, its completion is abnormal, or its text fails validation, stop before `send_template`; mark the job failed with a fixed non-sensitive diagnostic. Do not send a weather-only card or substitute a generic line. A valid `exact` line may proceed without a Gemini call or key. Invalid configuration also fails closed. The existing weather degradation is unchanged when content generation succeeds.

Run a safe CN preview with the override before considering live delivery. Preview jobs keep `SEND_MODE=dry-run` and never load `WECHAT_*`. A preview log currently prints the completed message, including the generated or exact line; do not assume Actions Secret masking also hides a substring of the JSON Secret after it has become a rendered message. Only use text suitable for that private-repository log and its authorized readers. The preview's fixed source marker says `manual` or `generated` without leaking raw theme or credentials. A separately triggered preview and a later scheduled/live run each make their own Gemini request: a *theme* preview is an illustration, not a frozen approval of the exact future wording. An `exact` override for the same date is byte-for-byte stable subject to the existing template rendering. Inside any single live run, assemble/validate the final line once and pass that same value to the send step; never regenerate between inspection and sending. When CN daily live is eventually enabled by a separate decision, skip the automatic CN preview job for that schedule event; otherwise the two scheduled jobs would call Gemini independently and display different lines. Manual CN preview remains available. Do not automatically re-run a failed live send because delivery may be uncertain.

## Verification and rollout

- Unit tests cover `exact > theme > default`, both fields together, absence and date matching across Shanghai midnight, stale overrides, malformed/duplicate-key JSON, invalid text, exact-text Gemini bypass, API failure without fallback, full-candidate rejection of multiline or quoted generated text, no `send_template` on failure, English/length/template limits including the rendered field, and sanitized diagnostics.
- Tests cover the local helper's validation and stdin-only Secret update with mocked `gh`; no real Secret value appears in test fixtures or output. Check that CN jobs receive the override and US/self jobs do not, and preserve the current owner/branch/slot/first-attempt gates.
- Test on the feature branch and with a real replacement Gemini Key only through GitHub's safe CN preview. A previously exposed Key must be revoked and replaced before use; never read, print, or paste a value into chat. Confirm the preview step's `generated` or `manual` marker, not the mocked unit-test log.
- Merge and any CN phone test are separate decisions. `ENABLE_CN_DAILY` stays off until Carlos separately confirms both intended phone receipts and content and explicitly chooses to turn on daily delivery. A green preview or accepted API response alone is not phone receipt.
